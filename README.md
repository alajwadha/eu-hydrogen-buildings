# Hydrogen in residential heating and the power system

This repository contains the model code, country profiles, dashboard, and manuscript source for:

> **Hydrogen in residential heating and the power system: a merit-order and capital-recovery assessment for 29 European markets**
> Abdurahman Alsulaiman (LEURE, EPFL) and Ali Alajwad (RENEW Lab, Johns Hopkins University; Cornell University)
> Manuscript prepared for *Applied Energy*

A spatially-resolved techno-economic model of residential heating decarbonisation across **EU27, Switzerland, and the United Kingdom** at NUTS3 regional resolution, 2025–2050. The model evaluates the conditions under which decarbonised hydrogen deployment in buildings is economically and environmentally justified relative to heat pump electrification.

**The submission and how to reproduce it:** the canonical LaTeX source is
`paper/ae_submission/` (`V7.tex` plus `SI.tex`), and
[`paper/ae_submission/REPRODUCE.md`](paper/ae_submission/REPRODUCE.md) maps every
headline number in the manuscript to the script that produces it. That file supersedes
this README wherever the two differ. `paper/` also holds a longer working version of the
same analysis, which is not the submitted document.

## Research questions

The submitted manuscript states one question with two sub-questions:

- **Main:** Under what conditions, and where, is decarbonised hydrogen justified in the buildings sector of the EU-27, the United Kingdom and Switzerland, relative to heat-pump electrification, by 2050?
- **Sub-question 1:** Under which scenarios does hydrogen come into consideration at all, tracing the demand trajectory and the resulting heating mix?
- **Sub-question 2:** In which cases is hydrogen competitive *to run*, judged as a dispatchable option against the gas boiler and the gas peaker on operating cost rather than against the heat pump on levelised cost, and what does that imply once the capital recovery of the winning plant is tested?

Switzerland, a high-cost, hydro-rich and cavern-poor system reliant on imported hydrogen, is a compact standalone case tied to the second sub-question.

## Quick start

```bash
git clone https://github.com/alajwadha/eu-hydrogen-buildings.git
cd eu-hydrogen-buildings
pip install -r requirements.txt    # Python 3.10+

# Reproduce the published numbers: the bottom-up demand basis, all four scenarios,
# the sensitivities, the power arena and the generated LaTeX tables, in dependency order
cd code && PYTHONPATH=. python -m scripts.rebuild_local

# Or drive the stages by hand. --demand bottomup is required: it is the basis every
# number in both manuscripts sits on, and the flag defaults to the Hotmaps benchmark
# basis instead, which reproduces a different demand level
python run.py --skip-download --samples 200 --demand bottomup

# Regenerate the figures the two manuscripts actually use (the P-series). This reads the
# result CSVs the line above writes, so run it after, not before
cd code && PYTHONPATH=. python -m scripts.paper_figures

# Check that every figure still clears the printed-legibility floor
cd code && PYTHONPATH=. python -m scripts.check_figure_print_scale
cd code && PYTHONPATH=. python -m scripts.check_figure_overlap

# Regenerate dashboard data
python code/scripts/generate_dashboard_data.py
cp dashboard/data.js docs/data.js && cp dashboard/data.js data.js

# Build the Applied Energy submission (the canonical documents). Five tables and the
# validation table are generated, not hand-written, so rebuild_local (or the individual
# emitters: h2_gap_analysis, infrastructure_bill, cold_snap_duration_sweep,
# capacity_payment, global_sensitivity_econ, make_validation_table) must run first
cd paper/ae_submission
pdflatex V5.tex && bibtex V5 && pdflatex V5.tex && pdflatex V5.tex   # → V5.pdf
pdflatex SI.tex   && bibtex SI   && pdflatex SI.tex   && pdflatex SI.tex     # → SI.pdf

# Build the longer working version (not the submitted document)
./Build.sh                         # → paper/Paper_v20.pdf
```

UK data: `code/data/raw/uk/ts044_accommodation_ltla.csv` is committed; only re-download from ONS TS044 on a fresh clone if missing.

## Scenarios

| Scenario | Description | HP share 2050 | H₂ share 2050 | Demand change 2050 |
|---|---|---|---|---|
| `CURRENT_POLICIES` | Current-measures freeze | 29.1% | 0.5% | −5% |
| `STATED_POLICIES` | Announced policy delivered | 36.5% | 5.5% | −9% |
| `NET_ZERO` | Climate-neutrality-consistent | 47.5% | 3.5% | −31% |
| `H2_PUSH` | Deliberately hydrogen-favourable | 38.8% | 8.5% | −18% |

(Demand-weighted across 29 countries, 200-sample bottom-up MC. These are the raw
shares; the papers renormalise them to sum to 100 per cent, which moves the heat-pump
column to 29/37/49/39, so the two sets are the same result on two bases. Demand reduction is the
emergent LMDI net of population, household-size and envelope-renovation drivers,
not an imposed target. Earlier 30-sample interim values, 49/7/30 etc., are
superseded.)

Every assumption is logged with its source in `literature/assumptions_register.md`. The register is the working record behind the Methods section, so it carries more detail, and more open questions, than the submitted paper needs.

## Key features

- **NUTS3-resolution** building stock for 29 countries (1,397 NUTS3 regions in the
  building-stock table; the demand surface it feeds carries 1,369). The layer supplies
  the *share* of each region's dwellings in each of three building types, which is what
  the demand build consumes. Its `dwellings_2021` column is a normalisation base and not
  a dwelling count: the values are on inconsistent bases across countries and the UK's
  are shares already, so summing the column is meaningless. `BuildingStock.py` says so at
  the point of construction.
- **Eight technologies** (gas boiler, oil boiler, biomass boiler, electric boiler, ASHP, GSHP, district heat, H₂ boiler) with full LCOH 2025–2050
- **Country-specific labour-cost multipliers** on CAPEX and FOM (Eurostat lc_lci_lev 2024; EU27=1.00, range 0.35 BG → 1.80 LU). See `literature/assumptions_register.md`.
- **ETS2 carbon-price trajectories** (LOW/CENTRAL/HIGH) applied via `Policy.py`
- **Monte Carlo** uncertainty propagation (default 200 samples, 30-sample interim default for fast iteration)
- **Three OIES hydrogen import scenarios** (ET08 2022, ET32 2024, STRANDED)
- **D3 interactive dashboard** showing country-level LCOH, tech shares, fuel prices

## Paper figures

The figures in the two manuscripts are the `P`-series in `paper/figs/paper/`, produced by
`code/scripts/paper_figures.py` and the per-figure generators beside it
(`fig_model_flow.py`, `power_merit_order.py`, `power_dispatch.py`, `heat_dispatch.py`,
`fig_uc_results.py`, `fig_winloss_heatmap.py`, `graphical_abstract.py` and others).
`paper/ae_submission/REPRODUCE.md` names the generator for each one alongside the claim
it supports.

`code/src/Visualise.py` produces an older `fig3`–`fig14` series that no current
manuscript includes. It is kept because the dashboard and the country profiles still
draw on it.

Every generator that draws small labels calls `_figstyle.assert_printable()`, which fails
the build if a declared font size would print below 6 pt once the figure is scaled into its
column. That guard only sees the sizes an author writes down, so it misses two things:
matplotlib renders a mathtext sub- or superscript at 0.70x the declared size, and a tick
formatter can pick its own sizes. `python -m scripts.check_figure_print_scale` closes the
gap by reading the font sizes out of each finished figure PDF's content stream and scaling
them by the inclusion width, so it reports what the renderer will actually set rather than
what the generator intended. It found five inclusions printing 5.2 to 5.8 pt type that both
the declared-size guard and its own earlier scale proxy passed.

Legibility and layout are separate defects, so there is a second checker.
`python -m scripts.check_figure_overlap` draws every figure, asks matplotlib's renderer
where each piece of text actually landed, and reports any two that collide, plus any
callout pinned over the data. It found twenty-one collisions, including two axis labels
running through each other, panel letters printed on tick labels, and a legend row sitting
on the descenders of an axis label. The house rule it enforces is that a figure carries no
callout over its data: what a callout would say goes in the caption, the legend or the panel
title, where it cannot collide with anything. Both checkers run inside
`paper/ae_submission/check_submission.py`.

These are tracked in `PLAN.md` and `literature/assumptions_register.md`. The most consequential ones:

1. **Fuel-price uncertainty** — RESOLVED (2026-06): `price_mult_{carrier}` is now wired through `compute_lcoh` in the MC, so the per-carrier draws move the tech-mix/emissions bands.
2. **HP / DH feasibility scores** (SFH HP=0.9, MFH HP=0.5, SFH DH=0.3, MFH DH=0.8) are expert judgement only — pending Abdul validation.
3. **Hungary regulated gas price** €31/MWh — anomaly distorting LCOH; flag in paper.
4. **Biomass = zero-emission** under EU RED II is the model default; contested.
5. **OIES paper citations** ET08 (2022) vs ET32 (2024) — Abdul to confirm which is the canonical reference.
6. **Building stock "OTHER" category** dominates the type split in most regions — addressed by EUBUCCO integration. Note this concerns the *share* between types; the `dwellings_2021` column is a normalisation base, not a count, and nothing downstream reads its level.
7. **Country labour multipliers** sourced from Eurostat lc_lci_lev 2024 — replace with UN/SAMI data if Abdul prefers.

Every numerical claim in the results section traces to the `code/results/mc_summary_*.csv`, `mc_country_*.csv` and `mc_emissions_*.csv` outputs of the four scenarios. Every per-country claim traces to the corresponding YAML in `countries/{name}/data/profile.yaml`. Every assumption is logged in `literature/assumptions_register.md` with provenance and status tag.
