## Documentation conventions for new work

When adding a new module, dataset, or methodology decision:

1. **Code-level docs** — put a comprehensive docstring at the top of the script. Include: purpose, inputs, outputs, decision rules, justifications, parameter sources, known limitations.
2. **Project-level methodology doc** — for anything paper-worthy, create or update a Markdown file in `literature/` (subfolder if it's a multi-file topic, like `literature/luxembourg/`).
3. **Assumption-level docs** — append a dated entry to `literature/assumptions_register.md` describing the assumption, source, formula, and status.
4. **Update this index** (`DOCUMENTATION.md`) with the new doc's location.
5. **Commit message** — describe what changed and why. Reviewers and your future self will read these.

## Citation template for the paper

For any methodology contribution to the model that's documented here, cite the project repository in your methods section. The repository commit hash at submission time is the version-of-record.
